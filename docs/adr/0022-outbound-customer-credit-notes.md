# ADR-0022 — Controlled outbound customer credit notes

## Status

Accepted.

## Context

Outbound invoices already have a deterministic canonical model, official OIOUBL
validation, immutable document archival and idempotent delivery. Customer credit
notes need the same evidence chain while retaining the relation to the credited
invoice and translating Dolibarr's negative accounting values to positive UBL
document amounts.

## Decision

The outbound provider accepts only validated native Dolibarr standard invoices
and credit notes. A credit note must link through `fk_facture_source` to one
validated standard invoice in the same entity and for the same customer.

The canonical model carries an explicit `CreditNote` document type and credited
invoice reference. Negative Dolibarr line, VAT and total values are converted to
positive canonical values without changing the underlying bookkeeping.

The generator emits the UBL `CreditNote-2` root, `BillingReference`,
`CreditNoteLine` and `CreditedQuantity`, including the OIOUBL-specific monetary
total required by the pinned official Schematron. Generated bytes must pass the
official XSD and Schematron before archival as `oioubl_credit_note`. The existing
transport boundary accepts this archive type and retains its content-hash-based
idempotency and immutable receipts.

## Consequences

- missing, cross-customer or unvalidated original references are rejected;
- the same credit note produces deterministic XML and cannot be delivered twice;
- invoice behavior remains backward compatible through the default canonical type;
- response messages, Peppol and aggregate over-credit policy remain separate scopes.
