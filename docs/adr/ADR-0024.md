# ADR-0024 — P0 production deployment receipt evidence

## Status

Accepted.

## Decision

A registered deployment must have a signed deployment receipt in addition to the signed deployment attestation.

The receipt is verified against the same pinned attestation trust store and contains the deployment identifier, production environment, deployment timestamp, approver, approval period and change/release reference.

The runtime binds the receipt to the active deployment attestation before the deployment-attestation monitor can pass.

## Rationale

The deployment attestation describes the approved hosting, backup and control configuration. The receipt is the per-deployment evidence that the approved configuration was actually deployed for a specific change. Requiring both prevents a static, still-valid attestation from being treated as proof that an arbitrary production deployment is approved.

## Fail-closed behaviour

Missing, unreadable, unsigned, expired, future-dated or deployment-mismatched receipts make the deployment-attestation monitor fail. The P0 release collector therefore cannot produce a passing deployment-attestation gate.

## Operational boundary

The application verifies the signed evidence contract. Production deployment tooling remains responsible for generating the receipt, protecting the signing key, recording the change reference and retaining the receipt with deployment records.
